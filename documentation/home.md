# Conduit Documentation

Welcome to Conduit — a small, pragmatic DSL and runtime for defining and executing node-based data pipelines. This documentation covers core concepts, quick-start instructions, node syntax, Rust node implementations, expressions, control flow, and examples to help you build pipelines that are composable, testable, and performant.

Start here if you want a concise overview of the project, where to find examples, and how to implement your own nodes in Rust.

Key concepts

- Nodes: Units of work that accept inputs and produce outputs.
- Inputs: Named parameters or a default unnamed input that a node consumes.
- Store: A simple shared state abstraction for holding values across a pipeline.
- Pipelines: Directed acyclic graphs that connect node outputs to inputs.

# The Code Clarity Manifesto

Conduit exists to restore clarity and agency in software development. As AI accelerates code generation, its real value comes when humans can read, reason about, and direct the resulting systems. Conduit provides a lightweight, human-first layer: workflows that compose small, testable blocks.

### The problem

AI can produce working code quickly, but the result is often opaque. Teams find themselves maintaining large bodies of machine-generated code they cannot easily inspect, reason about, or evolve.

### The solution

Introduce a readable composition layer. In Conduit, you assemble blocks—single-responsibility units—into workflows. Implementations (the block internals) can be generated, downloaded, or authored, but the workflow reveals program behavior at a glance.

### Principles

- Human-first: workflows are concise, readable, and expressive.
- Composability: build once, reuse everywhere.
- Testability: blocks are small and easy to test in isolation.
- Observability: failures point to workflow steps, not to opaque implementation details.

### Conceptual example

The same email-signup flow can be expressed as a long function or as a simple workflow:

```conduit
# function-style (opaque)
# 247 lines of authentication logic ...

# workflow-style (readable)
workflow UserSignup:
  receive -> validate -> create_account -> send_welcome_email -> redirect

  on error -> log -> notify_admin -> show_friendly_message
```

With the workflow, the behavior is explicit: you can swap, test, or replace a single block without touching the rest of the pipeline.

Blocks

A block is a focused unit of work (for example: "send email", "resize image", "charge card"). Blocks expose clear inputs and outputs so they can be composed into workflows. Implementations are free to be written in Rust, JavaScript, or generated by AI—what matters is the block contract.

Why this matters

1. You stay in control — you decide composition and failure handling.
2. Code becomes reusable and shareable across projects.
3. Debugging is faster because you can localize failures to a single step.
4. AI becomes more reliable when it works within well-defined boundaries.
